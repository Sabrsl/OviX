B. BUGS CRITIQUES
================================================================================

1. FRONTEND EN ÉTAT DE LOADING PERMANENT - CRITIQUE
   Fichier: frontend/src/pages/Dashboard.tsx
   Cause: systemApi.getSystemStatus() bloque tout le chargement
   Impact: Application entièrement inutilisable
   Comportement attendu: Dashboard devrait charger même si un service ne répond pas
   Comportement actuel: Page reste en "Chargement..."

2. TIMEOUT DE RÉCUPÉRATION D'ARTICLES - MAJEUR
   Fichier: frontend/src/api/client.ts
   Cause: Timeout initial 30s trop court
   Correction appliquée: Timeout augmenté à 300s (5 min)

3. DIFF NON AFFICHÉ DANS ARTICLEDETAIL - CRITIQUE
   Fichier: frontend/src/pages/ArticleDetail.tsx
   Cause: Pas de récupération du diff depuis le backend
   Impact: L'utilisateur ne peut pas voir les modifications proposées
   Solution nécessaire: Endpoint /api/diff/{job_id}/{article_title}

4. FILTRES RÉCUPÉRATION - VÉRIFICATION NÉCESSAIRE - MAJEUR
   Fichier: backend/api/routes/articles.py
   Cause: Filtres appliqués une seule fois, pas par lots comme Streamlit
   Impact: Résultats différents entre Streamlit et React
   Tests nécessaires: Vérifier exclude_published et include_analyzed

5. LOGS NON VISIBLES DANS TERMINAUX - MAJEUR
   Fichier: utils/logging_config.py
   Cause: Possible buffering stdout ou redirection Uvicorn
   Impact: Impossible de déboguer le système
   Vérification nécessaire: PYTHONUNBUFFERED=1, niveau DEBUG

6. CONFIGURATION DISPERSÉE - MOYEN
   Fichiers: AnalysisNew.tsx, Settings.tsx
   Cause: Configuration IA locale, pas centralisée
   Impact: Incohérence de configuration

J. LOGS
================================================================================

CONFIGURATION ACTUELLE (utils/logging_config.py):
  - level: INFO
  - handlers: StreamHandler(stdout), FileHandler, LogCapture

PROBLÈME IDENTIFIÉ:
  - Théorie: Logs devraient s'afficher dans stdout
  - Réalité: Terminal backend semble silencieux

CAUSES POSSIBLES:
  1. Buffering stdout (Python buffer par défaut)
  2. Uvicorn redirige stdout différemment
  3. Processus enfants n'héritent pas handlers
  4. Logs seulement au niveau WARNING/ERROR par défaut
  5. Some modules n'utilisent pas logging (print statements)

VÉRIFICATION NÉCESSAIRE:
  1. Vérifier si Uvicorn capture stdout
  2. Vérifier buffering avec PYTHONUNBUFFERED=1
  3. Vérifier que tous les modules utilisent logging
  4. Tester niveau DEBUG
  5. Vérifier logs dans fichier logs/app.log
